## Done (cont. 6)
- [x] **Production DB**: switched Prisma Client's runtime driver to `@prisma/adapter-libsql` (`lib/db.ts`) so the same code path runs against a local SQLite file *and* Turso — only `DATABASE_URL`/`TURSO_AUTH_TOKEN` differ between environments. Extracted the file-path resolution into `lib/db-url.ts` with a dedicated regression test: `@libsql/client` resolves relative `file:` URLs against `process.cwd()`, not the schema's directory the way Prisma CLI does — without the fix, local dev would have silently pointed at a different, empty database file. Caught and fixed before it shipped, not after.
- [x] **Vercel Blob for resume upload**: `app/admin/(protected)/resume/actions.ts` now uploads to Vercel Blob when `BLOB_READ_WRITE_TOKEN` is set (production), falling back to `public/uploads` locally — closes the gap where uploads would have silently failed on Vercel's read-only runtime filesystem.
- [x] `.github/workflows/ci.yml`, `CLAUDE.md`, `.env.example` updated with the full Turso + Vercel Blob deployment procedure (see `CLAUDE.md` § Deployment).
- `/code-review` (medium) on the driver-adapter swap found a real version-compatibility issue — fixed: top-level `@libsql/client` was pinned to `^0.18.0`, outside `@prisma/adapter-libsql@6.19.3`'s declared support range (`^0.3.5`–`^0.8.0`); downgraded to `^0.8.0` to match. Also added a fail-fast check: a remote `libsql://` `DATABASE_URL` without `TURSO_AUTH_TOKEN` now throws immediately instead of attempting a silent unauthenticated connection. One reviewer finding (claimed a missing `previewFeatures = ["driverAdapters"]` flag was required) was checked against this Prisma version's actual behavior — `prisma generate` itself reports the flag as deprecated/unneeded here, and the adapter was empirically verified working (build, dev server serving real seeded data, and all 33 tests reading/writing through it) — so that finding was not acted on.
- Second `/code-review` pass found 3 more issues — fixed: `isRemote` classification now uses the *resolved* URL (post `resolveDatabaseUrl`) instead of the raw env value, so it can't diverge from what's actually passed to the adapter; auth token is now only forwarded when the connection is actually remote (was passed unconditionally, harmless but sloppy); resume upload now deletes the previous file/blob after a successful new upload (was accumulating unboundedly) and uses a collision-resistant filename instead of a bare timestamp; `.env.example`'s `TURSO_AUTH_TOKEN` uncommented for consistency with the other required vars.
- Verified: `npm run build`/`lint` clean, `npm run test` 19/19, `npm run test:e2e` 14/14 (33 total), dev server confirmed serving real DB content through the new adapter.
